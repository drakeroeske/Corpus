## Known issues / decisions
- Not browser-tested by Claude (per CLAUDE.md); verified by unit tests + type-check + build only. Barcode camera, Open Food Facts/USDA calls and the 3D body still need a check on a real phone.
- Large lazy chunks: ThermalBody ≈ 830 kB (three.js), Scanner ≈ 480 kB (zxing); only loaded when opened.
- "Save as meal" names the meal with the browser prompt dialog.
- The thermal palette (#FF6A2B stop) in the 3D body is the one deliberate exception to the Riso palette (DESIGN.md).
- Redesign verified by type-check, tests and build only; needs a look on a real phone (fonts, grain strength, contrast).
- Weights are stored in the user's chosen unit; switching units converts stored data.
- HashRouter is used so static hosting and iPhone home-screen launches need no server config.
- Deload trigger reads "readiness < 55 for 5+ consecutive days" as a trailing streak of daily scores under 55.
- Readiness: any missing input (not just HRV) is redistributed proportionally; HRV needs at least one prior-week value as baseline.
- Weekly volume counts secondary muscles as 0.5 sets.
- The Phase 1 prototype's data (DB `corpus`) is not migrated; v1 uses a fresh DB `corpus-v1`.
